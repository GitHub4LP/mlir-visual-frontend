# 定义层 v0：种类 = ⟨参数, 约束, 语义⟩

原型：`model/defs.py`；检验：`model/defs_test.py`（含与真实 MLIR 的差分）。
运行：`PYTHONPATH=model python3 model/defs_test.py 600`

## 1 问题
v4 只有 op 一层对组合封闭：用户能组合出 op，却不能定义类型、属性和接口，只能用 MLIR 给的。这一轮让这四类实体（type、attribute/property、interface，以及由它们构成的 ADT）由同一个定义机制产生，原生的和用户的同构。原生的以 trust=builtin/ods 导入，用户的以 trust=user 定义，下游机制不区分两者。

## 2 静态项：attribute 与 type 统一（§1）
- 种类 Kind = ⟨名字, 类别 type|attr, 参数（每个参数有自己的种类）, 约束, 打印⟩。项 Term = ⟨种类, 参数⟩，良构 = 参数种类正确 + 种类约束成立，并递归到子项。
- 已登记：IntegerType、IndexType、IntegerAttr、StringAttr、ArrayAttr、TypeAttr、SymbolRefAttr、UnitAttr，以及 arith 的 OverflowFlagsAttr（ods）。
- **L8 属性按指称存储**：IntegerAttr 存位模式，不存字面量。`3 : i2` 与 `-1 : i2` 是同一个项。字面量范围规则与 MLIR 一致：signless 两种读法都接受，signed/unsigned 只接受各自的范围。
- 差分（D1）：600 个随机字面量与嵌套数组，接受与否、规范打印与 MLIR 解析器 600/600 一致。

## 3 参数（property）与元数据（可丢弃 attribute）（§2）
- 每个 op 的参数 = ⟨名字, 接受条件（静态部分 + 值域公式）, 指称, 默认值, 是否必需⟩。core 只看到指称（例如 overflowFlags → nuw 布尔），所以**只有参数能进入语义**，元数据在构造上就影响不到 Sem。
- **L9 命名空间分离**。真实 MLIR 有两个行为证明元数据不能当成无类型的键值表：
  1. 元数据字典里出现与参数同名的键（`{overflowFlags = #arith.overflow<nuw>}`），MLIR 会把它提升为参数，nuw 真的生效。所以“附加元数据”可能悄悄改变语义。
  2. 未知的参数名（`<{bogus = 1}>`）被静默丢弃。
  模型对两者都拒绝，登记为保守（P1、P2）。
- 差分（D2）：600 个随机节点（类型错误、越界、缺失、未知名、同名元数据），一致 521，保守 79（全部来自 P1/P2），不可靠 0。差分还抓出一个模型错误：越界的 predicate 只算出了值域公式，却没有报错。已修。

## 4 复合 op 的参数（§3）
- 体内节点可以用 `$k` 引用复合 op 的参数。**L10**：参数约束 = 体内每个使用点的约束代入后取合取（精确，E）；静态部分（种类、类型）必须逐点一致，否则在定义处报错。
- 语义上，参数是摘要里的符号（z3 Int/Bool），实例化时代换，与端口同构。
- D3：`cmpk(a, b)` 的 k 用作 cmpi 的 predicate，推出约束 0 ≤ k ≤ 9，k 取 −3..12 时与 MLIR 16/16 一致；参数化摘要在全部 20 组参数下嵌套 ≡ 内联；把 k 声明成 i3 时，在定义处报“predicate 须为 i64”。

## 5 用户类型（ADT）（§4）
- `define_adt(名字, 变体)` 一次生成三样东西：z3 sort；op（构造、判别、投影，投影到错误的变体得到毒值）；降级（1:N 类型转换：判别位 i1 + 各变体字段，以及每个 op 的降级实现，都是普通的复合 op）。
- 生成的 op 和复合 op 一样可以派生 caps，例如 option.some.val 派生为 Pure。这就是“与原生地位相同”。
- **L11 降级正确性 = 抽象函数下的数据精化**：∀ 降级输入 x̂，¬UB_A(abs x̂) ⇒ ¬UB_L(x̂) ∧ (¬P_A ⇒ ¬P_L ∧ abs(out_L) = out_A)。
  - 必须用抽象函数（降级 → 抽象，多对一），不能用表示函数（抽象 → 降级）。none 的载荷可以是任何值；表示函数要求它等于某个规范值，会**错误地拒绝**正确的降级（D4 复现）。
  - 定义期逐 op 检查一次（8/8 通过），错误的 is_some、交换字段的 pair.mk 都被抓到。
  - 程序级：随机程序（含 scf.if 返回 option、以 is_some 为条件）做 1:N 降级，200/200 整体精化，即“逐 op 精化 ⇒ 程序精化”。变异测试中，生成器起初从不让 is_some 影响输出，坏的 is_some 0/100 被抓；修正生成器后 9/100 被抓。
- 外部检验（第 30 轮，adtjit_test A11）：降级并内联后的程序交给同一提交 MLIR 的 JIT，穷举降级输入。抽象语义直接在 z3 Datatype 上求值，与 abs(JIT 输出) 比较：100 个程序、89766 个有定义的输入，不符 0；错误的 is_some 降级被抓到 3403 个输入。
- 整值毒值比 LLVM 的逐字段毒值更粗，但降级方向是精化（目标更有定义），所以可靠。

## 6 interface（§5）
- 接口 = ⟨方法（以 Self 为类型的签名）, 定律⟩；**实现表与类型定义分开**，所以第三方可以给原生类型加实现（MLIR 的 external model），用户的接口也能用在原生类型上。
- 实现分三档：
  - **derived**：能力直接由 Schema 派生，例如 MemoryEffects 来自 Eff，Speculatable 来自 caps；
  - **checked**：定律已被证明；
  - **declared**：只是声明（例如 ODS 声明了接口，前端却没有可执行实现），**不能用于推导或改写**。
  这样区分了“宣称有某能力”和“真的拥有它”。
- **L12 接口定律是定向精化，不是等式**。毒值和 UB 会让正确的实现也满足不了等式。D5 的结果：

| 实现 | 结合律 | 左单位元 | 右单位元 |
|---|---|---|---|
| i3 回绕加法 | ⇄ | ⇄ | ⇄ |
| i3 nuw 加法 | ⇄ | ⇄ | ⇄ |
| i3 减法 | ✗ | ✗ | ⇄ |
| option 取第一个 some | 只有 ← | ⇄ | 只有 → |

  “取第一个 some”的结合律只能从右结合改写成左结合：a 是 some、b 是毒值时，(a⊕b)⊕c 有定义，a⊕(b⊕c) 却会对毒值分支而触发 UB。改写引擎只能使用已证明的方向（law_ok）。这直接就是下一步 rewrite 契约的判据 Sem(g) ⊑ Sem(rewrite(g))。
- 泛型复合 op：`reduce3<T: Monoid>` 在实例化时查实现表；类型没有实现时拒绝实例化。

## 7 已知边界
- ADT：字段只能是标量，至多 2 个变体，不支持递归类型（列表、树）。
- attribute 种类只是子集：缺 Dense、Float、AffineMap、Dictionary。
- 参数只能在值上是符号的，类型参数必须静态；复合 op 参数的默认值推导没做。
- 泛型只做单态化：泛型 op 本身没有摘要，编辑器在实例化之前看不到它的事实。要给泛型摘要，需要以“未解释函数 + 定律公理”推导，这是下一个要解决的元层问题。
- 方言（命名空间、版本、依赖）与 IRDL 导出还没做。
