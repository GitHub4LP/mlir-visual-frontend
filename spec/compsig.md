# 复合 op 的多态类型签名（类型层 v1）

实现：`model/compsig.py`；检验：`model/compsig_test.py`（`PYTHONPATH=model python3 model/compsig_test.py 90`，约 2 分钟）。
签名的条目接口（`typesig.items / ok / label`）与原生 op 共用。复合 op 注册进 `typesig.COMPS`，`typesig.check` 不区分原生和复合。

## 1 问题
第 7 轮之前，复合 op 的端口类型由用户写死，是单态的。用 muli/addi 搭出的 axpy 只能用在一种类型上，而 `arith.addi` 本身对 i8、index、`tensor<?xi8>`、`vector<4xi32>` 都成立。复合 op 因此弱于原生 op，违反“与原生同地位”。

## 2 做法
- 端口不标类型。体内每个值的类型是端口类型的表达式：`p | 常量 | elt(e) | with(e, t)`。表达式由各 op 的推断规则得到，这些规则与 MLIR 一致：ODS 自动生成的 InferType、TypesMatchWith，以及“结果为 Index”。
- 体内每个节点的每个签名条目（端口约束和关系）都代换成端口表达式上的约束。合取起来得到 Φ(端口)。
- 内部变量的 ∃ 消去在这里就是代换：内部类型是端口类型的函数，所以不需要量词。
- 表达式规范化：`i1s(e) = with(e, i1)`，`with(with(e, a), b) = with(e, b)`。
- 结果写成表达式，等于复合 op 自动获得了 InferType。

示例（随机生成，原样输出）：
```
c0: ∀ p0, p1.  (p0, p1) → (with(p1, i8))
    Φ: IndexCastTypeConstraint(p1) ∧ _ixcast(p1, with(p1, i64)) ∧ narrower(with(p1, i64), with(p1, i8)) ∧ shape(…) ∧ …
```

## 3 组合律
- **L25 签名闭包。** 复合 op 的签名与原生签名是同一种数据，走同一个 check，因此可以继续嵌套。判据有两条：Φ(T) ⇔ 内联后逐节点检查 ⇔ MLIR verifier；嵌套签名 ≡ 展开后的签名。
- **L26 结果类型的选择必须能相对表达。**
  - trunci、extui、index_cast 这类 op 的结果类型由用户选择。如果在复合 op 里把它写成字面量（如 `i8`），复合 op 就失去了形状多态。
  - 所以前端需要 `with(x, t)`，意思是“与 x 同形状、元素为 t”。
  - MLIR 的 IR 里没有这种写法，只有 C++ builder 有。这是前端必须**强于 MLIR IR** 的一处：复合 op 是用户在 IR 层定义的，而 MLIR 的同类定义要写成 C++。
- **L27 端口投影可靠，但不完备。**
  - connectable 只看自由变量仅含该端口的约束：不会把可连的判成不可连，但可能把不可连的判成可连（要等其余端口确定）。
  - “是否可实例化”在有限类型池上判定，强度为 S：池外的类型覆盖不到。

## 4 检验结果
- **C1** Φ ≡ 体 ≡ MLIR：1043 个实例（MLIR 接受 612 个），三方全部一致。
  - 复合 op 按类型导向生成：先取一个见证类型，只接受在见证下良类型的节点。
  - 实例类型包括：换容器形式、换元素类型、改动单个端口、完全随机。
  - 推不出的内部类型用随机类型占位，以此检验“换成别的内部类型也不能让它合法”。
  - 另有 37 例 MLIR 崩溃（第 7 轮发现的那两类 verifier 缺陷），Φ 全部拒绝。
- **C2** 嵌套 ≡ 展开：900/900（接受 494 个）。
- **C3** 端口投影：共 2520 个（端口, 类型）组合。有补全却被判为不可连的是 0；判为可连、实际找不到补全的是 34/1772（1.9%）。
- **C4** with 与字面量（只统计含“用户选择结果类型”的 op 的复合 op）：接受的实例从 1428 降到 241；能用于多种容器的复合 op 从 8/10 降到 4/10。
- **C5** 代价：推导一个签名 0.4 ms；Φ 检查 35 µs（与按体检查相当）；connectable 13 µs。
- **C6** 定义期判定“可实例化”：90 个随手连的复合 op 中只有 26 个能实例化，其余 64 个在定义时就能报“永远无法使用”。先用端口投影剪枝，平均 0.8 ms。
- 回归：typesig 6696/6696；core、transform、shape、edit 全部通过。

## 5 缺口
- 推断只有正向（由操作数推结果）。无法反向推断，例如由结果类型确定端口类型。
- 结果推不出、又无法用 with 表达的 op（from_elements、splat、empty、cast），只能写字面量，复合 op 在这些位置是单态的。真正需要“类型变量的 ∃”（内部类型不由端口决定）的情况尚未支持。
- 复合 op 的端口没有变长组。
- 值层仍按具体类型单态化，每个具体类型重新推导一次。签名层的多态还没有传到值层。
