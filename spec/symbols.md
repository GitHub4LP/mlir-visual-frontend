# 符号层（第 14 轮）

## 1 复盘：一项从未在真实 IR 上被检验过的义务
`structure.py` 的 S1 重名、S2 解析、S3 可见性、S4 调用签名，都只读手工字段：`sym`、`vis`、`callee`、`ftype`。
`irimport` 导入的真实 IR 把属性原样放进 `props['_attrs']`，从不设置这些字段。由此有两个后果：
- 第 12、13 轮 C2 的“结构层误拒 0”，在符号义务上是**空检验**：真实 IR 上 S1–S4 从未触发。
- C2 只把单个函数装进一个新模块，又给它补上 `ftype`。这样做恰好绕开了 R8（函数类型对入口块参数、对 return）对手工字段的依赖。

本轮第一次把**整个模块**交给 `structure.check`：2108 个合法模块中误拒 2031 个。原因有三处：
- R8 读 `ftype` 字段，导入节点上取到的是缺省值 `() -> ()`；
- 符号使用的类型表是模块级的全局表，而真实 IR 中每个函数都有 `%arg0`，值名只在隔离区域内唯一；
- 对未知 op（transform 方言）的空区域误判为 R1。

教训：“0 误拒”还要问一句——这条义务在被测分布上到底触发过没有。每项义务都要报告**被检查的实例数**（本轮 Y1：110 个真实符号使用）。

## 2 来源
| 部分 | 来源 |
|---|---|
| 定义者（SymbolOpInterface，含经 `baseInterfaces` 的继承，例如 FunctionOpInterface → Symbol） | ODS 的 trait/interface 闭包（`symtab.interfaces`） |
| 符号表（SymbolTable trait） | ODS；`builtin.module` 不在 12 方言的 .td 里，按 MLIR 内建规则登记 |
| 使用者（SymbolUserOpInterface） | ODS：`func.call`、`func.constant`、`memref.get_global` |
| 名字、可见性、引用、函数类型 | `_attrs`：`sym_name`、`sym_visibility`、引用属性、`function_type`。手工字段仍可用（core 原生图） |
| 解析规则（MLIR 核心机制 SymbolTable.cpp） | 扁平引用在使用者的最近符号表中解析，不上溯，也看不见嵌套表内部；嵌套引用逐表下行；同表重名 |
| 使用义务（C++ `verifySymbolUses`，declared） | `symtab.USES`：每个使用者登记三项——引用属性、目标 op、关系（`call` 端口类型等于函数类型；`fn` 结果等于函数类型；`ty` 结果等于全局的 `type`） |

导入账（Y0）：定义者 4 个，符号表 1 个（另有内建模块），使用者 3 个，全部登记了义务，未登记 0。

## 3 外部真值检验（`model/symtab_test.py`）
- **Y1**：MLIR 测试集中 MLIR 接受的 2108 个模块，整模块检查，**误拒 0**。修正前误拒 2031。期间实际检查了 110 个真实符号使用。
- **Y2 变异差分**：以真实模块为底，只改动符号层，交 MLIR 判定，共 6089 例，**一致 6089**。其中我们拒而 MLIR 收的为 0，MLIR 以符号理由拒而我们收的为 0。

| 变异 | 我们 / MLIR | 数 |
|---|---|---|
| 引用改成不存在的名字 | 拒 / 拒 | 86 |
| 引用改成同模块中的另一个符号 | 拒 / 拒 220；收 / 收 82 | 302 |
| 两个符号重名 | 拒 / 拒 | 632 |
| 改目标的可见性（同表） | 收 / 收 | 4631 |
| 目标移入嵌套模块 `@inner`，引用写成 `@inner::@f` 或 `@f`，可见性三种 | 拒 / 拒 | 438 |

- 嵌套引用 `@inner::@f` 加 public 的 73 例中，有 49 例最初只被 MLIR 拒绝：三个使用者的引用属性都是 FlatSymbolRefAttr。把属性层（第 13 轮）并入判定后，这 49 例全部抓住。这正说明两层要联合判定。
- **限度**：12 方言中没有接受嵌套引用的使用者，所以“嵌套 + public ⇒ 接受”这一方向在外部真值上**未被检验**（S3 的嵌套可见性规则仅由 structure.py 的自测与 MLIR 对照）。

## 4 组合律
- **L36a**：符号层的拒绝蕴含 MLIR 拒绝。依据 Y1、Y2。
- **L36b**：对登记了使用义务的使用者，符号层与 MLIR 一致。依据 Y2，范围限于被测分布：扁平引用、同表或一层嵌套。
- **L37（推论）**：调用节点的**补全候选** = 最近符号表中目标种类正确、关系成立的符号。Y2 的“改成另一个符号”一栏共 302 例，与 MLIR 逐例一致，其中候选 82 个、非候选 220 个，所以这个候选集是精确的，不是近似。

## 5 对前端的指导
- 符号是前端“定义—引用”的载体：子图调用、全局数据。编辑一个定义（改名、改函数类型、改可见性）时，重新检查的范围是它所在符号表内的全部使用者。这些使用者可以从符号表上索引出来，不需要全图重查。
- 前端的作用域规则必须与 MLIR 相同：扁平引用不上溯。前端若允许“外层可见”，降级时必须生成嵌套引用；而本文的三个使用者都不接受嵌套引用，等于这样的引用无法降级。
