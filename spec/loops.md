# 位宽、index 与循环 v0

实现在 `model/core.py`，检验在 `model/loop_test.py`。
运行：`PYTHONPATH=model python3 model/loop_test.py 300`（约 8 秒）。W2 跑 1500 个程序约 30 秒。

## 1 值层是多 sort 的
- `iN` 用任意位宽的位向量。`i3` 只为穷举预言机（core_test.py）保留。
- `index` 用数学整数 ℤ，目标位宽 `IW` 是 DataLayout 参数（默认 64）。
- 新增的 op：muli/andi/ori/xori，以及 trunci/extui/extsi/index_cast/index_castui。现有 op 都同时支持 iN 和 index。
- pattern 逐位宽证明（Alive 式的有界验证）：i3/i8/i16/i32/i64 下，有效规则全部证明，错误规则全部反驳，i64 耗时 1.2 秒。
  - 常量参数必须用同位宽的位向量。用 ℤ 再转换，在 i8 以上会让 z3 卡住。

## 2 组合律
- **L17″ index 按 2^IW 回绕（第 21 轮更正，laws.md §2）**：LangRef 规定无标志的 addi/subi/muli 结果为数学值 mod 2^n，index 同样如此；只有 nsw/nuw 使溢出成为毒值。下面的 L17′ 被 LangRef 与 JIT 否定（`(x+1) > x` 在 L17′ 下可证，MLIR 在 x=2^63−1 执行得假），仅作历史保留；“代价”一条在 L17″ 下仍然成立（回绕代替毒值）。
- ~~L17′ index 溢出是毒值~~（第 6 轮修订；原 L17 为 UB）。
  - 结果超出 IW 位有符号范围时为毒值，值项仍是数学结果；值域公理写成“毒值 ∨ 在范围内”。MLIR 的回绕是它的精化。
  - 修订原因：原 L17 下，index 上的 addi 不可推测，而 MLIR 把它标为 Pure，前端因此弱于 MLIR（LICM 等被挡住）；slice∘slice 融合也不成立（shapes.md S4）。
  - 代价：不变式要自己带范围事实。`c = i − lb` 在 lb < 0 时可能溢出，所以不再归纳，要加上 lb ≥ 0。原 L17 下，溢出被单独算成 UB，这个事实因此被隐藏了。
  - 修订后的检查：循环体的检查假设边界非毒值（边界是毒值时循环本身是 UB）。
- **L18 循环摘要 = 按结构命名的未解释函数。**
  - 静态边界且趟数 ≤ 64：精确展开。
  - 否则：输出 = `n>lb ? F(边界, 初值, 捕获) : 初值`。F 的名字由循环体与命名无关的结构哈希决定。
  - 由此：`cnt(p) − cnt(p) = 0` 可证（确定性）；不同的循环是不同的函数；嵌套 ≡ 内联仍然成立。
  - 体有效应（读内存）时，结果改为非确定的新变量，摘要不精确。
  - **透明模式在调用点特化**：摘要不精确时，按实参重推导体，`cnt(5)` 得到 5，恢复与内联相同的精度。不透明模式只用摘要，可靠但不完备。
- **L19 不变式先做归纳检查，再作为公理进入摘要。**
  - 公理以入口条件为守卫：`入口满足 inv ⇒ 出口满足 inv`，“体不 UB”也是这样。因此即使入口不满足，公理本身也无条件可靠；入口检查只用来出诊断。
  - 例：不变式 `c = i − lb` ⇒ 输出 = n − lb。体内有 `100 / (i+1)` 时，不变式 `i ≥ lb ≥ 0` 让 `lb ≥ 0 ⇒ 不 UB` 可以证明；没有不变式时证不出。
  - 非归纳的不变式被忽略。
  - 随机具体输入下，展开得到的值都满足摘要的公理（30/30）。

## 3 与真实 MLIR 执行的差分
- 随机程序：i8/i32/i64/index、类型转换、select、cmpi、nuw、嵌套静态 scf.for。降到 LLVM 后由 JIT 执行，与模型求值比较。
  - 1500 个程序（925 个含循环），6000 组输入：**一致 5118，不一致 0**；模型判为 UB 741、判为毒值 141（这些情形下任何结果都是精化）。
- 差分抓到了实现 bug：ℤ↔位向量的化简表用 AST id 做键，id 被回收复用后得到错误结果（1000 组里错 3 组）。现已改为保留引用，并按项比较。

## 4 求解器代价的边界
- ℤ↔位向量的转换是 z3 的弱点：`iN → index → iN` 往返恒等，i8 需要 8.8 秒，i16/i32 在 20 秒内得不到结果。
- 对策有两条：
  - 直接相邻的往返在位向量里化简；
  - `prove` 有超时，超时或 unknown 一律按“未证明”处理（可靠方向），并计数（STATS）。本轮全部检验中 unknown 为 0。
- 对前端的指导：类型转换尽量留在边界上；编辑器在“未证明”时要说明是因为超时，而不是给出反例。

## 5 对前端的指导
- 循环的事实分三档：
  - 静态展开：精确；
  - 结构摘要：确定性、相等性可用，数值事实未知；
  - 有不变式：由用户声明，经归纳检查后可用。
- 编辑器可以提示“这个循环的结果未知，加一个不变式就能证明 X”。
- 不变式通不过归纳检查时直接给出诊断；入口不满足时也给出诊断，但已证明的事实仍然可靠。

## 6 已知边界
- scf.while、多块 CFG 的值层还没有做。
- isl 的传递闭包（仿射循环的精确摘要）没有并入。迭代域里的步长同余条件没有使用。
- 不变式目前是 Python 函数；规范上应是约束语言里的表达式。
- `ub.poison` 和 load 产生的新变量在同一复合 op 的多次实例之间是共享的（此前已有的限制）。
- 形状/extent（tensor、memref）还没接到 index 值上，这是下一步的工作之一。

## 7 第 26 轮：L18 的名字漏掉了参数（model/loopsum_test.py）

**发现。** 第 26 轮审查 L18 的前提：摘要函数的名字只编码结构（canon），所以结构之外凡影响语义的东西都必须作为实参传入，或进名字。逐项清点后，有两项不满足：
1. **复合 op 参数。** 循环体里的 `arith.constant {value = $k}` 在 canon 中序列化成字面串 `'$k'`，参数值既不在实参里，也不在名字里。于是 `addk<1>(n) ≡ addk<2>(n)` 被“证明”成立——透明模式（调用点特化）和不透明模式（项代换）都如此。JIT 跑内联后的两段循环，n=1 时差为 −1。这是不可靠方向的错误。
2. **语义开关**（IW、IXOVF、REMSI_MIN、FLAGS_EXT、NSW）不在名字里。若在 IW=64 下推导的摘要与 IW=32 下推导的摘要进入同一查询，两者会被当成同一个函数。

**修正（L18′）。** 体内引用的参数（`param_refs`，含嵌套区域）按名字排序后追加到实参：特化时是具体值，不透明时是 pconst，实例化时由代换替换。语义开关编码进名字（`sem_tag`）。

**检验。**
| 检验 | 结果 |
|---|---|
| U0 回归 | 修前两种模式都错误地证明 addk<1> ≡ addk<2>；修后两种模式均不可证，addk<1> ≡ addk<1> 仍可证；JIT n=0..3 的差为 0、−1、−2、−3 |
| U3 | 同一循环在 IW=64 与 IW=32 下的摘要名不相交 |
| U1 证伪（MLIR 文本 → irimport → valimport → derive，JIT 为真值） | 有效变异 458 个（常量、op、操作数次序、谓词、初值、捕获值、下界、步长），模型证明相等 0，因而不可靠 0 |
| U2 完备性 | 相同结构 342/342 可证相等 |
| 回归 | loop_test W1–W5 全部符合，W2 1200 输入不一致 0；defs_test 参数化摘要闭包 20/20；core_test、transform_test 不变 |

**批判。** U1 在构造上抓不到第 1 项：MLIR 文本里没有复合 op 参数。它只能证伪“名字漏掉了文本中可见的东西”，而结果表明文本中可见的部分没有遗漏。第 1 项是靠清点 L18 的前提发现的，不是随机检验发现的。剩余风险同样只能靠清点来控制：值层读取的任何全局状态都必须进 `sem_tag`。今后新增全局开关时，须同步修改 `sem_tag`。

## 8 第 29 轮：L19 外部化与归纳变量越界

### 8.1 L19 的外部证据（loop_test W6）
- 随机构造循环：步长 1–3，增量 ±，初值 0 或 5；候选不变式由 7 个原子随机组合。
- 对被接受的不变式，把模型公理、具体输入和“输出 = JIT 值”联立求解，要求可满足：160/160。
- 灵敏度：把出口 iv 篡改为 ub 后，在 67 个输入中抓出 25 个。
- 注意：只检查“不变式在真实输出上成立”是不够的，那只检验了不变式本身的真假。必须检验模型的公理。

### 8.2 归纳变量越界：MLIR 自身不一致
- 例子：`scf.for %i = 2^63−2 to 2^63−1 step 4`。
  - LangRef 的文字是“iv ∈ [lb, ub) 才执行”，按此应为 1 趟；canonicalize 也把它折叠成 1 趟。
  - `convert-scf-to-cf` 降级只比较 iv < ub。iv 回绕成负数后循环继续，JIT 在 O0 和 O2 下都不终止（20 s 超时）。
- 模型的处理：此前按 1 趟展开，比降级后的程序“更有定义”。现在“最后一趟的 iv + st ≥ 2^(IW−1)”判为 UB，两种行为都是它的精化。
- W6 越界探针回归：越界输入中模型未判 UB 的为 0。
- upstream issue 只起草、不提交（须用户同意）。要点：scf.for 的文档与 canonicalize 的趟数语义，和 SCFToControlFlow 的降级在 iv 溢出时不一致；应在文档中明确溢出是 UB，或在降级中加溢出检查。
